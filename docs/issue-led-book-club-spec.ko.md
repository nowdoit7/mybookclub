## 1. 한 줄 정의

사용자와 서로 다른 독서 성향의 AI 참가자들이 같은 책을 미리 읽고, 각자의 관점에 맞게 준비된 발제를 중심으로 생각과 경험을 나누는 독서회.

## 2. 문제 정의

현재 제품은 참가자 간 의견 차이를 만들기 위해 반론과 대립을 강제한다. 이 방식은 대화를 역동적으로 만들 수 있지만, 실제 독서회보다 토론 대회나 논쟁 시뮬레이터처럼 느껴질 수 있다. 모든 발언이 찬반 구조에 들어가면서 캐릭터가 책에서 발견한 고유한 질문, 개인적 인상, 다른 작품과의 연결도 좁아진다.

사용자가 원하는 경험은 누가 이기는 토론이 아니다. 같은 책을 읽은 사람들이 발제를 하나씩 꺼내고, 각자 자기 생각을 설명하며, 자연스럽게 공감하거나 다른 해석을 보태는 모임이다.

## 3. 제품 원칙

### 3.1 발제는 찬반 명제가 아니다

발제는 “동의하는가?”만 묻는 문장이 아니라 여러 해석을 열어 두는 질문이어야 한다.

- 나쁜 예: “문수의 행동은 정당하다. 찬성하는가?”
- 좋은 예: “문수가 신을 잃은 뒤에도 굿판을 밀어붙인 힘을 우리는 무엇이라고 봐야 할까?”

### 3.2 각 참가자는 답변자가 아니라 준비해 온 독자다

AI 참가자는 직전 발언을 받아치는 역할만 하지 않는다. 책의 근거와 자신의 독서 성향을 바탕으로 미리 생각한 관점, 질문, 장면을 가지고 모임에 들어온다.

### 3.3 공감과 비공감은 결과이지 의무가 아니다

시스템은 반대를 강제하지 않는다. 같은 생각이면 왜 공감하는지 확장하고, 생각이 다르면 어느 지점에서 갈리는지 설명한다. 억지 합의와 억지 반론을 모두 피한다.

### 3.4 근거 없는 깊이보다 확인 가능한 대화를 우선한다

책에 관한 정보가 충분히 검증되지 않았다면 구체적인 장면과 인물을 지어내지 않는다. 근거가 부족한 발제는 생성하지 않거나 일반적인 독서 질문으로 낮춘다.

### 3.5 사용자는 평가 대상이 아니라 동등한 참가자다

AI는 사용자의 독해를 정답·오답으로 채점하지 않는다. 사용자의 발언도 이후 발제, 후속 질문, 마무리 기록에 실제로 반영한다.

## 4. 목표

1. 사용자가 “AI에게 질문받는 경험”보다 “실제 독서회에 참여한 경험”을 느끼게 한다.
2. 한 세션에서 성격이 다른 독서 관점이 최소 3개 이상 분명히 드러나게 한다.
3. 강제 반론 없이도 의미 있는 공감, 차이, 확장이 발생하게 한다.
4. 모든 구체적 작품 발언을 검증된 책 정보 또는 사용자가 제공한 내용에 연결한다.
5. 사용자의 핵심 의견이 세션 마무리와 회고 문서에 누락되지 않게 한다.

## 5. 비목표

- 승자나 정답을 결정하는 토론 대회
- 모든 발언에 반드시 반론을 붙이는 구조
- 책 전문을 저장하거나 긴 문장을 그대로 인용하는 기능
- 첫 버전에서 사용자가 발제문을 직접 작성·관리하는 고급 운영자 기능
- 여러 명의 실제 사용자가 동시에 참여하는 실시간 멀티플레이

## 6. 대상 사용자

### 핵심 사용자

책을 읽고 생각은 남았지만 주변에 함께 이야기할 사람이 없거나, 혼자서는 새로운 관점을 충분히 발견하기 어려운 독자.

### 보조 사용자

- 실제 독서회 전에 생각을 정리하고 싶은 독자
- 어려운 책을 다른 관점으로 다시 이해하고 싶은 독자
- 좋아하는 책을 여러 성향의 사람과 깊게 이야기하고 싶은 독자

## 7. 핵심 사용자 경험

### 단계 0. 책 확인

1. 사용자가 제목과 저자를 입력한다.
2. 시스템이 실제 책과 판본·작품 범위를 확인한다.
3. 동명이거나 불확실하면 사용자에게 후보를 보여주고 확인받는다.
4. 확인되지 않은 책은 그대로 진행하지 않는다.

### 단계 1. 참가자 선택

1. 사용자가 함께할 AI 참가자 3명을 선택한다.
2. 각 참가자 카드에서 직업·독서 성향·주로 보는 관점을 확인한다.
3. 알렉스는 고정 진행자로 참여한다.

### 단계 2. 비공개 사전 준비

모임 시작 전 시스템은 다음 작업을 수행한다.

1. 책의 기본 정보, 인물, 주요 사건, 장면, 주제, 배경, 논쟁거리와 출처를 정리한다.
2. 각 참가자는 자신의 성향에 따라 발제 후보 1~2개를 만든다.
3. 시스템은 중복되는 발제를 합치고, 서로 다른 관점을 끌어낼 발제 2개를 최종 선정한다.
4. 각 발제에 가장 잘 맞는 주도 참가자와 보조 참가자를 배정한다.
5. 발제 내용과 배정 결과는 모임 시작 전에 사용자에게 공개하지 않는다.

### 단계 3. 소개

1. 알렉스가 모임을 환영한다.
2. AI 참가자들이 이름, 배경, 책을 읽는 방식을 짧게 소개한다.
3. 사용자가 이름, 참여 계기, 책을 읽은 이유를 이야기한다.
4. 이 단계에서는 책의 해석을 논박하지 않는다.

### 단계 4. 첫인상

1. 참가자들은 다른 사람의 답을 참고하지 않고 준비한 첫인상을 독립적으로 말한다.
2. 사용자가 첫인상을 말한다.
3. 누구도 즉시 평가하거나 반론하지 않는다.

### 단계 5. 인상 깊은 장면

1. 각 참가자가 서로 다른 장면 또는 서로 다른 이유를 중심으로 이야기한다.
2. 사용자가 기억에 남은 장면을 말한다.
3. 잘못된 장면 정보가 감지되면 단정적으로 정정하기보다 책 근거를 확인하고 부드럽게 구분한다.

### 단계 6. 발제 라운드

각 발제는 다음 순서로 진행한다.

1. 알렉스가 발제의 배경과 질문을 짧게 제시한다.
2. 해당 발제에 배정된 주도 참가자가 자기 관점에서 먼저 말한다.
3. 다른 참가자 1~2명이 독립적인 생각을 보탠다.
4. 사용자가 자신의 생각을 말한다.
5. 참가자들은 필요한 경우에만 공감, 비공감, 질문 또는 다른 작품·현실 사례를 연결한다.
6. 알렉스가 합의점을 만들지 않고 “같은 점, 갈리는 점, 새로 열린 질문”을 정리한다.
7. 두 번째 발제로 넘어간다.

### 단계 7. 마무리

1. 사용자와 참가자들이 오늘 가져갈 생각을 한 가지씩 말한다.
2. 알렉스가 사용자의 핵심 의견과 발제별 관점 차이를 정리한다.
3. 회고 문서에는 발제, 주요 관점, 사용자의 기여, 남은 질문, 확인된 참고 자료가 포함된다.

## 8. 발제 설계

### 8.1 좋은 발제의 조건

- 책의 구체적인 사건·장면·주제에 연결된다.
- 한 문장으로 이해할 수 있다.
- 정답을 전제하지 않는다.
- 최소 두 가지 이상의 해석 경로가 존재한다.
- 참가자의 성향에 따라 서로 다른 답이 나올 수 있다.
- 책을 읽은 사용자가 자신의 경험이나 판단을 보탤 여지가 있다.

### 8.2 발제 유형

- 인물 판단형: 인물의 선택과 책임을 어떻게 볼 것인가
- 관계 해석형: 인물 사이의 감정과 권력은 어떻게 움직이는가
- 구조·사회형: 작품의 사회적·역사적 배경이 사건을 어떻게 만든 것인가
- 형식·서술형: 시점, 구성, 문체가 독자의 판단에 어떤 영향을 주는가
- 경험 연결형: 작품의 상황을 우리의 현실이나 경험과 어떻게 연결할 것인가
- 작품 간 연결형: 다른 책과 비교할 때 무엇이 더 선명해지는가

### 8.3 캐릭터별 배정 원칙

발제는 캐릭터의 직업만 보고 배정하지 않는다. 다음 정보를 함께 사용한다.

- 관심 축
- 자주 사용하는 근거
- 쉽게 공감하는 지점
- 끝까지 의문을 유지하는 지점
- 이미 선택된 다른 발제와의 중복도

같은 발제를 모든 캐릭터가 똑같이 말하지 않도록, 각 캐릭터에게 별도의 “관점 임무”를 부여한다.

## 9. 기능 요구사항

### P0 — 첫 버전에 반드시 필요

#### P0-1. 책 검증 및 근거팩

- 실제 책 여부와 작품 범위를 확인해야 한다.
- 근거팩에는 제목, 저자, 작품 범위, 요약, 인물, 사건, 장면, 주제, 출처, 검증 상태가 포함되어야 한다.
- 검증되지 않은 내용을 구체적 사실처럼 말하지 않아야 한다.

수용 기준:

- 동명 도서가 있으면 사용자가 책을 확정하기 전 세션이 시작되지 않는다.
- 근거가 없는 장면을 발제나 AI의 기억으로 생성하지 않는다.
- 출처 부족 상태가 내부적으로 식별 가능하다.

#### P0-2. 참가자별 발제 후보 생성

- 선택된 참가자는 자신의 관심 축에 맞는 발제 후보 1~2개를 만든다.
- 각 후보에는 질문, 중요 이유, 근거 장면, 적합한 관점, 신뢰도가 포함된다.

수용 기준:

- 세 참가자의 발제 후보가 문장만 바꾼 동일 주제로 수렴하지 않는다.
- 발제마다 책의 근거가 최소 하나 연결된다.

#### P0-3. 발제 선정 및 배정

- 최종 발제 2개를 선정한다.
- 발제별 주도 참가자와 보조 참가자를 배정한다.
- 사용자에게는 해당 발제가 시작될 때 처음 공개한다.

수용 기준:

- 두 발제의 의미적 중복이 기준치 이하이다.
- 한 캐릭터가 모든 발제를 독점하지 않는다.
- 캐릭터의 성향과 발제 배정 이유를 테스트에서 설명할 수 있다.

#### P0-4. 발제형 세션 진행

- 소개 → 첫인상 → 인상 깊은 장면 → 발제 1 → 발제 2 → 마무리 순서를 지원한다.
- 첫인상과 장면 단계의 AI 발언은 서로 독립적으로 준비한다.
- 발제 라운드에서 반론을 강제하지 않는다.

수용 기준:

- 사용자는 각 발제에서 최소 한 번 자기 생각을 말할 기회를 얻는다.
- 자연스러운 공감은 허용되지만 의미 없는 칭찬과 반복은 제한된다.
- 의견 차이가 없더라도 시스템이 가짜 갈등을 만들지 않는다.

#### P0-5. 사용자 의견 보존

- 사용자의 핵심 주장과 정정 사항을 구조화해 이후 대화에 전달한다.
- 마무리와 회고에 사용자의 실제 기여가 포함된다.

수용 기준:

- 사용자가 말하지 않은 의견을 사용자에게 귀속하지 않는다.
- 사용자의 핵심 의견이 발제별 요약에서 누락되지 않는다.

#### P0-6. 품질 검사

- 발제 근거성, 관점 다양성, 반복도, 사용자 반영도, 자연스러움을 자동·수동으로 검사한다.

수용 기준:

- 프롬프트와 계약 스키마를 배포 전에 검사할 수 있다.
- Mock 세션과 실제 API 세션 모두 전체 흐름을 완주할 수 있다.
- 런타임 오류와 중단 지점을 기록한다.

### P1 — 빠른 후속 개선

- 사용자가 “조금 더 이야기하기 / 내 의견 말하기 / 다음 발제로 이동”을 선택
- 특정 발언을 선택해 답변하는 인용 카드
- 세션 길이 선택: 짧게, 보통, 깊게
- 발제별 참고 출처를 회고 화면에서 확인
- 사용자가 직접 발제 하나를 추가
- 모임 분위기 선택: 북카페, 세미나, 비평가 모임

### P2 — 향후 고려

- 실제 사용자 여러 명이 함께 참여
- 정기 독서 모임과 참가자 관계 기억
- 사용자가 만든 발제 라이브러리
- 독서 노트·전자책 하이라이트 연동
- 책 장르별 진행 방식

## 10. 품질 지표

### 출시 전 평가

- 발제 근거성: 구체적 발제의 95% 이상이 검증된 근거와 연결
- 발제 다양성: 한 세션의 최종 발제 2개가 서로 다른 관점 축 사용
- 캐릭터 식별성: 이름을 가린 발언의 화자 식별률 85% 이상
- 사용자 반영도: 회고에서 사용자의 핵심 주장 반영률 90% 이상
- 허위 장면률: 검증 세트에서 0%
- 세션 완주율: Mock 및 실제 API 시나리오에서 95% 이상

### 사용자 평가

- “실제 독서회에 참여한 느낌이었다” 평균 4.0/5 이상
- “새로운 관점을 얻었다” 응답 75% 이상
- “억지로 싸우는 느낌이었다” 응답 15% 이하
- “AI들이 같은 말을 반복했다” 응답 20% 이하

초기에는 실제 사용자 데이터가 없으므로 위 수치는 제품 가설로 사용하고, 10~20회의 휴먼 리뷰 후 조정한다.

## 11. 오류 및 예외 상황

- 책을 확인할 수 없음: 세션을 시작하지 않고 저자·ISBN·표지 등 추가 정보 요청
- 작품집 범위가 불명확함: 수록작 전체인지 특정 단편인지 확인
- 근거가 부족함: 구체적 장면 발제를 제외하고 사용자 메모를 요청
- 발제 후보가 중복됨: 하나를 제거하고 다른 관점 축으로 재생성
- 사용자 의견이 매우 짧음: 평가하지 않고 구체화 질문 한 번 제공
- 사용자가 책 내용을 잘못 기억함: 즉시 채점하지 않고 서로 다른 판본·기억 가능성을 확인
- API 실패: 현재 단계와 준비된 발제를 보존하고 재시도 또는 Mock 복구

## 14. 검토가 필요한 결정

### 결정 1. 한 세션의 발제 수

- 권장안: 기본 2개
- 이유: 3개 이상이면 반복과 피로가 늘고 사용자 발언 시간이 줄어들 가능성이 크다.

### 결정 2. 발제를 누가 준비했는지 공개할지

- 권장안: 사전에는 숨기고, 발제 시작 시에도 알렉스가 모임의 질문으로 제시
- 대안: “이 질문은 데브가 가져왔습니다”처럼 공개해 인물성을 강화

### 결정 3. 발제 라운드에서 사용자의 발언 순서

- 권장안: AI 두 명의 서로 다른 시각을 들은 뒤 사용자 발언
- 대안: 사용자가 먼저 말하고 AI가 확장

### 결정 4. 확인이 어려운 책의 처리

- 권장안: 구체적인 책 토론은 중단하고 사용자에게 추가 정보를 요청
- 대안: 사용자 제공 내용만 사용하는 제한 모드

### 결정 5. 다른 책의 인용 범위

- 권장안: 짧은 비교와 작품명 언급은 허용하되, 정확한 문장 인용은 검증된 경우만 허용

### 결정 6. 기본 세션 길이

- 권장안: 15~20분, 발제 2개
- 추후 짧게 8분 / 깊게 30분 모드 추가

## 15. 사용자 스토리

- 독자로서, 책이 정확히 확인된 뒤 모임을 시작하고 싶다. 그래야 존재하지 않는 장면을 두고 대화하지 않을 수 있다.
- 독자로서, 성향이 다른 참가자들이 준비한 질문을 듣고 싶다. 그래야 혼자서는 떠올리지 못한 관점을 발견할 수 있다.
- 독자로서, 동의나 반대를 강요받지 않고 내 해석을 설명하고 싶다. 그래야 평가받는 느낌 없이 참여할 수 있다.
- 독자로서, 내가 한 말이 뒤의 대화와 회고에 반영되길 원한다. 그래야 실제 모임의 구성원처럼 느낄 수 있다.
- 독자로서, 의견이 같을 때도 각자가 다른 이유와 경험을 보태길 원한다. 그래야 반복되는 AI 답변처럼 느껴지지 않는다.

## 16. 승인 기준

다음 항목에 합의하면 구현 명세로 전환한다.

2. 기본 발제 수와 공개 방식을 정한다.
3. 발제 라운드의 사용자 발언 순서를 정한다.
4. 확인이 어려운 책의 처리 정책을 정한다.
5. P0 범위와 품질 목표를 확정한다.
